## 1. Введение

Умножение разреженных матриц — ключевая операция в научных вычислениях, компьютерной графике и машинном обучении. Для больших разреженных матриц использование формата CRS (Compressed Row Storage) позволяет значительно сократить объём используемой памяти и ускорить вычисления за счёт работы только с ненулевыми элементами.

Ожидаемый результат: создание корректного параллельного решения, демонстрирующего ускорение за счёт распределения вычислительной нагрузки между MPI-процессами.

## 2. Постановка задачи

**Цель работы:** Реализовать и сравнить производительность последовательного (SEQ) и параллельного (MPI) алгоритмов умножения разреженных матриц в формате CRS.

**Определение задачи:** Для двух заданных квадратных разреженных матриц A и B размером N×N в формате CRS необходимо вычислить матрицу C = A × B также в формате CRS.

**Формат CRS (Compressed Row Storage):**
Матрица хранится в трёх массивах:
- `values` — массив ненулевых значений
- `col_indices` — массив индексов столбцов для каждого значения
- `row_ptr` — массив указателей на начало каждой строки

**Тип входных данных:**
```cpp
using InType = std::tuple<CRSMatrix, CRSMatrix>;  // A, B
```

**Тип входных данных:**
```cpp
using OutType = CRSMatrix;  // C = A × B
```

**Структура CRSMatrix:**
```cpp
struct CRSMatrix {
  int n = 0;                      // размерность матрицы
  std::vector<double> values;     // ненулевые значения
  std::vector<int> col_indices;   // индексы столбцов
  std::vector<int> row_ptr;       // указатели на строки
};
```
## 3. Базовый алгоритм (Sequential)

### Алгоритм последовательной реализации

Основной принцип работы заключается в последовательном обходе всех строк матрицы A и умножении каждой строки на соответствующие строки матрицы B с использованием хеш-таблицы для накопления результатов:

1. **Инициализация**
   - Получить на вход две разреженные матрицы A и B в формате CRS
   - Инициализировать результирующую структуру CRS для матрицы C

2. **Умножение матриц**
   - Для каждой строки i матрицы A:
     - Создать хеш-таблицу `acc` для накопления результатов
     - Для каждого ненулевого элемента A[i][k]:
       - Для каждого ненулевого элемента B[k][j]:
         - Накопить: `acc[j] += A[i][k] * B[k][j]`
     - Собрать ненулевые элементы из `acc` в результирующую строку

3. **Возврат результата**
   - Вернуть матрицу C в формате CRS

### Код последовательной реализации

```cpp
inline CRSMatrix MultiplyCRS(const CRSMatrix& A, const CRSMatrix& B) {
  CRSMatrix C;
  C.n = A.n;
  C.row_ptr.resize(C.n + 1);
  C.row_ptr[0] = 0;

  std::unordered_map<int, double> acc;
  std::vector<int> used_cols;

  for (int i = 0; i < A.n; i++) {
    acc.clear();
    used_cols.clear();

    for (int ia = A.row_ptr[i]; ia < A.row_ptr[i + 1]; ia++) {
      int k = A.col_indices[ia];
      double a = A.values[ia];

      for (int ib = B.row_ptr[k]; ib < B.row_ptr[k + 1]; ib++) {
        int col = B.col_indices[ib];
        auto& val = acc[col];
        if (val == 0.0) {
          used_cols.push_back(col);
        }
        val += a * B.values[ib];
      }
    }

    for (int col : used_cols) {
      double val = acc[col];
      if (val != 0.0) {
        C.col_indices.push_back(col);
        C.values.push_back(val);
      }
    }

    C.row_ptr[i + 1] = static_cast<int>(C.values.size());
  }

  return C;
}
```

## 4. Схема распараллеливания

### 4.1. Распределение данных

Для параллельной обработки используется ленточная горизонтальная схема распределения данных:
- Матрица A распределяется по строкам между всеми процессами (блочное распределение)
- Матрица B полностью дублируется на всех процессах через `MPI_Bcast`
- Каждый процесс обрабатывает свой непрерывный блок строк матрицы A

**Распределение строк:**
```cpp
int rows_per_proc = n / size;
int extra = n % size;
int start = rank * rows_per_proc + std::min(rank, extra);
int count = rows_per_proc + (rank < extra ? 1 : 0);
```



### 4.2. Схема связи
**Фаза 1: Рассылка матрицы B**

 - Процесс 0 рассылает размер и данные матрицы B всем процессам через MPI_Bcast

**Фаза 2: Локальное умножение**

 - Каждый процесс независимо умножает свой блок строк матрицы A на полную матрицу B

**Фаза 3: Сбор результатов**

 - Worker-процессы отправляют свои частичные результаты процессу 0 через MPI_Send
 - Процесс 0 собирает все результаты и формирует итоговую матрицу C

### 4.3. Декомпозиция задачи
**Декомпозиция по данным:**

 - Матрица A делится на горизонтальные блоки (непрерывные диапазоны строк)
 - Каждый процесс обрабатывает примерно N/P строк
 - Матрица B полностью реплицируется на всех процессах

**Псевдокод MPI-версии**

```cpp
function RunImpl():
    rank, size = MPI_comm_info()
    
    // Фаза 1: Рассылка матрицы B
    b_nnz = B.values.size()
    MPI_Bcast(b_nnz)
    MPI_Bcast(B.values, B.col_indices, B.row_ptr)
    
    // Фаза 2: Определение своего блока строк
    rows_per_proc = n / size
    extra = n % size
    start = rank * rows_per_proc + min(rank, extra)
    count = rows_per_proc + (rank < extra ? 1 : 0)
    
    // Фаза 3: Локальное умножение
    for i = 0 to count-1:
        global_row = start + i
        localC[i] = multiply_row(A[global_row], B)
    
    // Фаза 4: Сбор результатов
    if rank == 0:
        C = localC
        for p = 1 to size-1:
            MPI_Recv(p_data from p)
            merge p_data into C
    else:
        MPI_Send(localC to 0)
```

### Ключевые оптимизации

1. **Использование `unordered_map` вместо `map`:**
   - O(1) вставка и поиск вместо O(log n)
   - Значительное ускорение на строках с большим количеством ненулевых элементов

2. **Отслеживание использованных столбцов:**
   - Вектор `used_cols` позволяет избежать итерации по всей хеш-таблице
   - Сохраняет порядок появления столбцов

3. **Блочное распределение строк:**
   - Минимизация коммуникаций между процессами
   - Каждый процесс работает с непрерывным блоком памяти
